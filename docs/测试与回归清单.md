## 1. 自动化测试

### 1.1 执行方式

```bash
cd apps/backend
mvn test
```

- 测试不依赖 MySQL / Redis，使用 Mockito 模拟 Mapper 与中间件。
- 本机 JDK 17 / 23 均可运行；`pom.xml` 已覆盖 Byte Buddy 版本以兼容 JDK 23。
- 仅运行某个类：`mvn -pl qingshan-server -Dtest=CouponServiceImplTest test`。

### 1.3 测试边界

- 优惠券并发用例验证的是服务层对「条件更新返回 0」的处理；数据库行锁与条件更新 SQL 的并发效果仍需在预发环境用真实 MySQL 验证。
- 支付、微信登录、OSS 上传依赖外部服务，自动化测试只覆盖参数与状态校验，真实联调按手工清单执行。

## 2. 手工回归清单

### 2.1 管理端

| # | 场景 | 预期 |
| --- | --- | --- |
| A1 | 用种子管理员登录 | 提示修改初始密码；未改密前访问其他页面被拦截 |
| A2 | 修改密码后重新登录 | 旧 token 失效，新 token 可正常访问；`mustChangePassword` 为 false |
| A3 | 普通员工 token 调用管理员专属接口 | 返回 403「无权限执行该操作」 |
| A4 | 禁用员工后继续使用旧 token | 立即返回 401，需重新登录 |
| A5 | 商品改价 / 上下架 | 小程序下一次请求立即看到新数据（缓存版本号生效） |
| A6 | 店铺切换为打烊 | 小程序提交订单返回「店铺休息中，暂不接单」，无订单和库存变化 |
| A7 | 订单完整流转 | 接单 → 派送 → 完成；拒单/取消原因必填 |
| A8 | 售后退款 | 仅退款、退货退款、换货、补寄按发货状态限制；退款金额等于实付金额 |
| A9 | 优惠券管理 | 新建满减/折扣/代金/满折券、上下架、已发放券不可删除 |
| A10 | 手工物流轨迹 | 新增/删除节点后，小程序物流详情按时间倒序展示 |
| A11 | 字典与菜单 | A 电脑修改后 B 电脑重新登录看到相同配置；恢复默认可用 |
| A12 | 入库/出库 | 审核后库存与台账一致；并发审核只有一次成功 |
| A13 | 报表导出 | 导出 xlsx 可正常打开，金额/订单数与页面统计一致 |
